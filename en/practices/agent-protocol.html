Practices

Agent Operating Protocol#

Operating protocol#

Before making a non-trivial change, an AI agent should:

  1. Understand the user's actual intent.
  2. Inspect the existing implementation.
  3. Read relevant project documentation.
  4. Review architecture invariants and relevant ADRs (Architecture Governance).
  5. Check the existing toolchain and project conventions.
  6. Prefer existing dependencies and patterns.
  7. Make the smallest complete change that solves the requirement.
  8. Avoid unrelated cleanup.
  9. Run relevant validation.
  10. Review the resulting diff.
  11. Confirm that no accidental files or unrelated changes were introduced.
  12. Explain significant architectural, dependency, security, or behavioral changes.

Do not rewrite working code merely because you prefer another style.

Do not add an abstraction just because similar code appears twice; add one only when it solves a real maintenance, correctness, or architecture problem.

Memory behavior#

Agents with persistent memory should record that the project uses these guidelines.

Use memory to locate the relevant guidance. Treat repository files as the source of truth; they always take precedence over remembered rules or summaries.

During larger tasks, re-read the relevant guideline sections, especially:

  • At the beginning of substantial project work
  • Before architectural changes
  • Before adding or replacing dependencies
  • Before modifying CI/CD
  • Before changing toolchain configuration
  • Before changing UI language behavior
  • When existing project conventions are unclear
  • When remembered information conflicts with the repository

Never rely on a remembered summary when the repository has the current rule.

Hard rules quick reference#

The following behaviors are prohibited. Each item links to the document that defines the rule; keep this list synchronized with those documents whenever a rule changes.

  1. Replace mandatory standardized tools without explicit user approval. (core-principles)
  2. Use npm or yarn instead of pnpm. (typescript)
  3. Use ESLint as the project linter instead of oxlint. (typescript)
  4. Use Prettier instead of oxfmt. (typescript)
  5. Use Pipenv or Poetry instead of uv. (python)
  6. Use flake8 or black instead of ruff. (python)
  7. Use pre-commit or Lefthook instead of prek. (quality-gates)
  8. Replace Cocogitto with another Conventional Commits validator without a reason and approval. (git)
  9. Ignore lint or validation problems without understanding them. (core-principles)
  10. Disable useful rules just to make checks pass. (core-principles)
  11. Over-engineer rapid validation projects. (core-principles)
  12. Introduce unnecessary dependencies. (dependencies)
  13. Create redundant files or modules. (coding-standards)
  14. Silently violate an ADR. (architecture-governance)
  15. Accidentally change architectural invariants. (architecture-governance)
  16. Use non-English identifiers or comments in source code. (language-policy)
  17. Use Japanese romaji or Chinese pinyin as code identifiers. (language-policy)
  18. Infer UI language from conversation language. (language-policy)
  19. Produce low-quality literal translations in cross-language UI work. (language-policy)
  20. Upgrade GitHub Actions blindly, without reviewing compatibility. (github-actions)
  21. Commit secrets or sensitive information. (security)
  22. Force push shared history without approval. (git)
  23. Treat a green CI as proof that the implementation is correct. (change-discipline)
  24. Pin GitHub Actions to commit SHAs rather than current major-version tags, without a stated supply-chain policy. (github-actions)
