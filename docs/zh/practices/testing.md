# 测试策略

测试应当校验有意义的行为。

不要为了提高覆盖率而写测试。

添加测试之前,先弄清它要检测的失败模式。

优先覆盖:

* 核心业务逻辑
* 重要用户行为
* 已知的易错路径
* 边界条件
* 错误处理
* 异常情形
* 集成边界

覆盖率指标可以提供信息,但覆盖率百分比本身不是目标。

目标是对重要行为的正确运行有信心。

## 前端 E2E 测试

前端项目应在切实可行时包含 E2E 测试。

E2E 测试应聚焦:

* 主用户流程
* 关键产品行为
* 重要的集成行为

优先使用贴近真实的测试数据。

当接近生产环境的数据确有价值时,使用经过妥善匿名化或脱敏的数据。

永远不要在测试夹具中暴露敏感的生产信息。

控制 E2E 的执行时间。

不要构建庞大的 E2E 套件——既没有带来相应的信心,又显著拖慢快速校验流程(参见[质量门禁](../toolchain/quality-gates.md))。

## 前端单元测试

前端项目应在切实可行时,为重要组件和逻辑编写单元测试。

在能提升测试质量之处,使用真实的脱敏数据。

优先覆盖:

* 重要组件行为
* 业务逻辑
* 状态转换
* 数据变换
* 边缘情况
* 错误情形

保持单元测试快速。

避免只是重复实现细节的测试。
