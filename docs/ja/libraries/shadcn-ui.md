# shadcn/ui

## 判定

推奨 — Tailwind ベースのアプリケーションにおいては、shadcn/ui を推奨コンポーネントシステムとする。

## 使用する場面

- UI コンポーネントが必要な、Tailwind ベースのアプリケーションを構築する場合。
- ユーザーが別のコンポーネントライブラリやバージョンを明示的に要求していない、新規プロジェクト。

## 避けるべき場面

- ユーザーが別のコンポーネントライブラリやバージョンを明示的に要求した場合 — ユーザーの要求に従う。
- プロジェクトが Tailwind CSS を使っていない場合。shadcn/ui は Tailwind ベースのアプリケーション向けのコンポーネントシステムである。

## 長所

- コンポーネントはソースコードとしてリポジトリにコピーされ、内部を完全に確認・調整できる。
- 開発コスト、保守コスト、見た目の不統一、アップグレード時の競合、AI 生成コンポーネントの重複を削減できる。
- 公式のバリアントと設定機構で、コンポーネント内部を編集せずにほとんどのカスタマイズがまかなえる。

## トレードオフ

- コピーしたコンポーネントはアップストリームから乖離し得る。内部を改変するとアップグレードリスクが生じる。
- コンポーネントを公式実装に近い状態に保つには、規律ある運用が必要である。

## バージョン方針

- 新規プロジェクトでは、最新の適用可能な shadcn/ui セットアップを使う。
- ユーザーが別のコンポーネントライブラリやバージョンを明示的に要求した場合は、ユーザーの要求に従う。

## 利用ルール

- プロジェクトのセットアップでは、公式の shadcn/ui ドキュメントに従う。

### コンポーネントの再利用

- shadcn/ui コンポーネントを、合理的な範囲で可能な限り使う。
- カスタムコンポーネントを作る前に、shadcn/ui が適切なプリミティブやコンポーネントをすでに提供していないか確認する。
- 不必要な自作実装よりも、既存コンポーネント、既存コンポーネントの合成、公式バリアント、公式の設定機構を優先する。
- 目的は、開発コスト、保守コスト、見た目の不統一、アップグレード時の競合、AI 生成コンポーネントの重複を削減することである。

### 不要な改変を避ける

- ダウンロードしたコンポーネントは、公式実装に近い状態を保つ。
- テーマ変数、Tailwind 設定、合成、既存コンポーネントの API、標準バリアント、ラッパーコンポーネント、サポート対象のデザイントークンで実現できる変更のために、コンポーネント内部を改変してはならない。
- プライマリカラー、テーマ設定、タイポグラフィ、Markdown レンダリング、フォントサイズ、コンポーネントバリアントといった変更では、コンポーネント内部を直接編集する前に、shadcn/ui と関連する Tailwind の公式ドキュメントを確認する。

### 必須のオーバーライドを文書化する

- ダウンロードしたコンポーネントに本当に内部改変が必要な場合は、どのコンポーネントを、何を、なぜ変更したのか、その改変がどのアップグレードリスクを生むのかを文書化する。
- この情報はリポジトリ内の Markdown ドキュメントに残し、将来の開発者と AI エージェントが shadcn/ui のアップグレード時に乖離を把握できるようにする。

### shadcn MCP

- 開発環境が MCP に対応している場合、公式または適切な shadcn MCP 統合を優先する。
- MCP に対応したユーザーが shadcn/ui を使う際に MCP 統合が未設定であれば、エージェントはその設定を手伝ってよい。
