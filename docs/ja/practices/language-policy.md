# 言語ポリシー

言語の境界はプロジェクトの制約であり、明示的に扱わなければならない。

次の 3 つの概念は互いに独立である。

1. 会話言語
2. ソースコードの言語
3. プロダクト/UI 言語

ある言語から別の言語を推測してはならない。

正当なプロジェクトでは、次のような構成もありうる。

```text
Conversation: Chinese
UI: Japanese
Code: English
```

これらの言語はそれぞれ分離し、かつ自然なものでなければならない。

## コードの言語

ソースコードはすべて標準的な英語で書く。ただし、意図的に他言語を含むリテラル値は例外とする。

次の要素は英語で書かなければならない。

* 変数名
* 関数名
* メソッド名
* クラス名
* 型名
* インターフェース名
* 列挙型名
* モジュール名
* ファイル名
* ディレクトリ名
* コードコメント
* ドキュメント文字列
* 設定の識別子
* 内部のシンボル識別子

コードの識別子やコメントに英語以外の言語を使用しないこと。

特に、次のものを使用してはならない。

* 日本語のかな文字
* 日本語ベースの識別子
* 中国語ベースの識別子
* ピンイン(pinyin)による識別子
* ローマ字(romaji)による識別子

禁止される識別子のパターンには、次のようなものがある。

```text
kokyakuName
shinseiStatus
kehuName
yonghuId
```

代わりに、意味の明確な英語を使用すること。

```text
customerName
applicationStatus
customerName
userId
```

ASCII の要件を満たすためだけに、英語以外の単語をラテン文字へ音訳しないこと。

求められているのは**標準的な英語**であり、単なる ASCII ではない。

### リテラル値

リテラル値として意図的に他言語のテキストを含めることは認められる。例えば次のものである。

* UI の表示文言
* ローカライズリソース
* ユーザー向けのエラーメッセージ
* ローカライズされた内容を含むテストフィクスチャ
* ユーザーコンテンツの例
* 元の形式を保持しなければならないドメインデータ

リテラル値の存在は、英語以外の変数名やコメントを正当化しない。

## 会話言語

ユーザーが使用する言語で、自然にコミュニケーションをとること。

会話は次のようなものであるべきである。

* 自然である
* 友好的である
* 明瞭である
* その言語として慣用的である
* ユーザーのコミュニケーションスタイルに合っている

不必要な言語の混用を避ける。

中国語でやり取りしているとき、実装の内部で英語を使用しているという理由だけで、英語のフレーズを挿入しないこと。

次のものを指す場合は英語が適切である。

* コードの識別子
* API 名
* ライブラリ名
* コマンド
* プロダクト名
* 翻訳するとかえって分かりにくくなる、確立された技術用語

それ以外では、中国語で自然にコミュニケーションすること。

同じ原則は他の言語にも当てはまる。

## プロダクトと UI の言語

プロダクトの言語を、会話言語だけから推測してはならない。

プロジェクトの言語方針がまだ文書化されていない状況で、本格的なユーザー向けコンテンツを実装する前に、ユーザーへ次の点を確認すること。

* UI の主要言語
* 追加でサポートする言語
* 該当する敬語レベルやトーンの要件

確認できた言語ポリシーは、プロジェクトドキュメントに記録すること([必須プロジェクトドキュメント](project-documentation.md)を参照)。

一度記録したら、同じ質問を繰り返さずに従うこと。

再確認が必要なのは、次の場合だけである。

* ユーザーが要件を明示的に変更した場合
* 新しい要件が、文書化されたポリシーと競合する場合
* 求められる対象言語が、本当に曖昧な場合

ユーザーが会話言語を変えたからといって、黙って UI の言語を変更しないこと。

## 言語横断の品質

会話・コード・プロダクトの言語が異なるときは、ひと段と注意を要する。

言語間で文言を機械的に翻訳しないこと。

特に次の点を守ること。

* 中国語の影響を受けた日本語を作らない。
* 中国語の文構造を、不自然な形で日本語へ持ち込まない。
* 理由もなく、実装由来の英語を、それ以外は自然な中国語の会話にそのまま挿入しない。
* 同じドメイン概念の訳語を、UI 全体でばらばらにしない。
* 中国語の開発者会話から、日本語の UI 用語を推測しない。
* 英語のソースコード識別子から、中国語の UI 用語を推測しない。

ユーザー向け UI 文言は、次の優先順位で扱うこと。

1. 対象言語における標準的な用法
2. 正しい文法
3. 明確な意味
4. 適切な敬語レベル
5. 理解しやすさ
6. 使いやすさ
7. プロダクト全体との一貫性

UI のテキストは、直訳調や機械翻訳調ではなく、専門的で自然なものでなければならない。

重要な用語やトーンの選択に確信が持てない場合は、独断で慣習をでっち上げず、ユーザーに尋ねること。
