Rust ツールチェーン#

適用義務#

AI 支援開発のデフォルト言語は TypeScript と Python である。Rust はデフォルトではなく、次の要件が実際に必要な場合に限って選ぶ。

  • メモリ安全性と最大性能の両立
  • システムコンポーネント
  • 他言語向けのネイティブ拡張
  • WebAssembly ターゲット

Rust の採用には明確な根拠とユーザーの承認が必要であり、その内容をプロジェクトの ADR に記録する。

Rust に慣れていること自体は、採用の根拠にならない。

適用範囲#

本文書は Rust プロジェクトのベースライン標準であり、プロジェクト単位の評価に代わるものではない。Rust を採用する前に、要件が上記のいずれかに当てはまり、かつ TypeScript、Python、Go のいずれでも妥当なコストで満たせないことを確認する。

バージョン方針#

stable ツールチェーンを mise または rustup でインストールして使う。

Cargo.toml では edition 2024 を指定する。

nightly の機能はデフォルトで有効にしない。nightly が必要な場合は、明示的な決定として記録する。

利用ルール#

ビルドとパッケージング#

ビルドとパッケージングには cargo だけを使う。

標準の cargo コマンドを独自のビルドスクリプトでラップしてはならない。

フォーマット#

フォーマットには rustfmt を使う。

cargo fmt を mise タスクとして公開する。

リント#

リントには cargo clippy を使う。

CI では警告をエラーとして扱う：

cargo clippy --all-targets -- -D warnings

unsafe ブロック#

すべての unsafe ブロックには // SAFETY: コメントを付け、そのブロックの安全性を保証する不変条件を説明する。

借用チェッカーを回避する目的で unsafe を使わない。

エラー処理#

ライブラリのエラー型には thiserror を使う。

anyhow はバイナリの境界でのみ使う。ライブラリの公開 API に漏らしてはならない。

ワークスペース構成#

複数クレートからなるプロジェクトでは cargo ワークスペースを使う。

依存関係のバージョンは、ワークスペースレベルで同期する。

テスト#

CI では cargo test を実行する。

連携#

  • mise — バージョン管理：Rust ツールチェーンと関連ツールを mise で管理し、mise タスクとして利用できるようにする。
  • 品質ゲート — 同じチェック：prek と CI で同じリント・フォーマット設定を使う。
  • Git ワークフロー — コミット規律：Rust の変更も標準のコミットとプルリクエストのルールに従う。
  • テスト戦略 — テストの焦点：何をどのレベルで検証するか。
