AI コーディングガイドライン

AI エージェントとコードレビュアーのためのエンジニアリングガイドライン。ツールチェーン、日々の開発プラクティス、ライブラリ選定、プラットフォーム設計をタスク別に整理しています。

プロジェクトで使う

スキルをインストール

プロジェクトのディレクトリで実行し、現在のタスクにこのガイドラインを適用するようエージェントに指示してください。

pnpm dlx skills add fang2hou/ai-coding-guidelines@apply-guidelines

AI エージェントに直接指示する

スキルをインストールせずに、次の指示を AI エージェントに送ることもできます。

https://github.com/fang2hou/ai-coding-guidelines のガイドラインを現在のタスクに適用してください。
PORTAL.md から始め、タスクに対応する文書を順番に読み、関連する規約に従ってください。

まず読むべき基本文書

タスクに着手する前に、まずこの 2 本から読み始めてください。

  • 中核となるエンジニアリング原則ガイドラインの目的と、すべての判断の土台となる基本原則。
  • エージェント運用プロトコル変更を加える前に AI エージェントが踏むべき 12 ステップの行動手順。

カテゴリ別に探す

すべてのガイドラインを領域ごとに整理しています。

原則

1 件

判断の土台となる基本原則：速い検証、選択肢の絞り込み、根本原因の解決。

  • 中核となるエンジニアリング原則本ガイドラインは、AI 支援によるアイデアの迅速な検証と POC 開発におけるエンジニアリング標準を定める。

プラクティス

12 件

日々の開発プラクティス：コーディング規約、テスト、ドキュメント、依存関係、セキュリティ。

  • エージェント運用プロトコル自明でない変更を行う前に、AI エージェントは次の手順を踏むこと。
  • AGENTS.md の執筆AGENTS.md はリポジトリにおける AI エージェントの入口であり、コードを書く前に読み込む作業コンテキストである。エージェントツールはセッション開始時にこれを読み込み、保持できるコンテキスト量にも上限があるため、各行には作業に必要…
  • アーキテクチャガバナンスAI エージェントが誤って破ってはならないアーキテクチャの境界と不変条件を、ARCHITECTURE.md に明記する。
  • 変更の規律自明でない変更をレビューに回す前に、運用プロトコルに従い、このチェックリストでも確認すること。
  • コーディング規約選択した言語とフレームワークの確立された規約に従うこと。独自の流儀に置き換えないこと。
  • 角丸角丸は要素ごとに決める値ではなく、プロジェクト全体で揃える体系である。少数のトークン段階を一度定義し、すべての角丸をそこから選ぶ。 2 つのルールですべての場面を網羅できる。単一のサーフェスには連続角丸、ネストしたサーフェスには同心の角丸…
  • 依存関係の管理方針依存関係を追加する前に、次の 5 つの問いに順番に答えること。
  • 言語ポリシー次の 3 つの言語はそれぞれ独立して決めること。ある言語の選択から、ほかの言語を推測してはならない。
  • パイプラインこれらの規則は、GitHub Actions、GitLab CI、CircleCI、Jenkins など、あらゆるシステムの CI/CD パイプラインに適用する。選択したシステム固有の規則は、対応するツールチェーン文書に記載されている。
  • 必須のプロジェクトドキュメントすべてのプロジェクトは、AGENTS.md、README.md、DEVELOPMENT.md、CONTRIBUTING.md を維持しなければならない。重要なアーキテクチャ上の境界を持つプロジェクトでは、ARCHITECTURE.md も…
  • セキュリティ次のようなシークレットや機密情報をリポジトリにコミットしてはならない。
  • テスト戦略テストはカバレッジの数字を稼ぐためではなく、実際の振る舞いを検証するために書く。

ツールチェーン

9 件

言語ごとの標準ツールチェーン。ローカルと CI で同じツールを動かす。

  • Databricksデータおよび AI ワークロードでは Databricks を優先する。アプリケーションのホスティングと管理には Databricks Apps、スケジュール実行や自動実行には Databricks Jobs を使う。
  • Git ワークフロープロジェクトのすべてのコミットは、Conventional Commits 仕様に従わなければならない。
  • GitHub ActionsGitHub Actions は標準の CI/CD プラットフォームであり、ユーザーがパイプラインシステムを指定していない場合のデフォルトである。ツールに依存しないパイプラインの規則は パイプライン に記載されている。
  • Go ツールチェーンAI 支援開発のデフォルト言語は TypeScript と Python である。Go はデフォルトではなく、次の要件が実際に必要な場合に限って選ぶ。
  • misemise をすべてのプロジェクトで必須とする。
  • Python ツールチェーンPython と TypeScript は、ライブラリと AI エージェントのエコシステムが最も充実しているため、AI 支援開発のデフォルト言語とする。
  • 品質ゲートprek を標準のプリコミットフレームワークとして使う。
  • Rust ツールチェーンAI 支援開発のデフォルト言語は TypeScript と Python である。Rust はデフォルトではなく、次の要件が実際に必要な場合に限って選ぶ。
  • TypeScript ツールチェーンTypeScript と Python は、ライブラリと AI エージェントのエコシステムが最も充実しているため、AI 支援開発のデフォルト言語とする。
