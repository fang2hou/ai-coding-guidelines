12 件

日々の開発プラクティス：コーディング規約、テスト、ドキュメント、依存関係、セキュリティ。

  • エージェント運用プロトコル

    自明でない変更を行う前に、AI エージェントは次の手順を踏むこと。

  • AGENTS.md の執筆

    AGENTS.md はリポジトリにおける AI エージェントの入口であり、コードを書く前に読み込む作業コンテキストである。エージェントツールはセッション開始時にこれを読み込み、保持できるコンテキスト量にも上限があるため、1 行ごとに載せる…

  • アーキテクチャガバナンス

    AI エージェントが誤って破ってはならないアーキテクチャの境界と不変条件を、ARCHITECTURE.md に明記する。

  • 変更の規律

    自明でない変更は、運用プロトコル に加えて、レビューに回す前にこのチェックリストで確認すること。

  • コーディング規約

    選択した言語とフレームワークの確立された規約に従うこと。独自の流儀に置き換えないこと。

  • 角丸

  • 依存関係の管理方針

    依存関係を追加する前に、次の 5 つの問いに順番に答えること。

  • 言語ポリシー

    言語の境界はプロジェクトの明確な制約である。次の 3 つの言語はそれぞれ独立しており、1 つから別を推測してはならない。

  • パイプライン

    これらの規則は、GitHub Actions、GitLab CI、CircleCI、Jenkins など、あらゆるシステムの CI/CD パイプラインに適用する。選択したシステム固有の規則は、対応するツールチェーン文書に記載されている。

  • 必須のプロジェクトドキュメント

  • セキュリティ

    次のようなシークレットや機密情報をリポジトリにコミットしてはならない。

  • テスト戦略

    テストはカバレッジの数字を稼ぐためではなく、実際の振る舞いを検証するために書く。

    データおよび AI ワークロードでは Databricks を優先する。アプリケーションのホスティングと管理には Databricks Apps、スケジュール実行や自動実行には Databricks Jobs を使う。

  • Git ワークフロー

    プロジェクトのすべてのコミットは、Conventional Commits 仕様に従わなければならない。

  • GitHub Actions

    GitHub Actions は標準の CI/CD プラットフォームであり、ユーザーがパイプラインシステムを指定していない場合のデフォルトである。ツールに依存しないパイプラインの規則は パイプライン に記載されている。
