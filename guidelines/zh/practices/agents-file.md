# 编写 AGENTS.md

`AGENTS.md` 是仓库面向 Agent 的入口：Agent 在写下任何代码之前加载的工作上下文。Agent 工具会在开工前加载它，并对携带的指令上下文设有上限，因此每一行都必须值得占用这份空间。

模板：[project-agents.template.md](../../../templates/project-agents.template.md)

## 强制要求

每个项目必须在仓库根目录保留一份 `AGENTS.md`。

`AGENTS.md` 是规范文件名。不要把同一批规则复制到 `CLAUDE.md` 等兼容文件名中：重复的指令文件会各自漂移，并把上下文预算消耗两遍。

## 选择正确的载体

把每类指引放到它该去的地方：

| 内容                               | 归属                               |
| ---------------------------------- | ---------------------------------- |
| 长期生效的命令、约定、边界         | `AGENTS.md`                        |
| 产品背景、上手介绍、截图           | `README.md`                        |
| 完整的开发工作流与工具链细节       | `DEVELOPMENT.md`                   |
| pull request、评审与必须执行的校验 | `CONTRIBUTING.md`                  |
| 架构不变量                         | `ARCHITECTURE.md`                  |
| 只在某一个工作流中需要的操作步骤   | 独立文档或 Agent skill，用链接引用 |
| Agent 工具的偏好、默认模型、自主度 | 该工具自己的配置文件               |

不要把操作手册、长篇参考文档或与单个任务相关的笔记粘进 `AGENTS.md`。链接到事实来源即可。

## 结构

开头用一句话说明项目是什么、面向谁，随后按 Agent 最先需要的内容排列章节，与模板保持一致：

1. 命令——准确的环境搭建、运行、单条测试、测试、Lint、类型检查、构建、重新生成与完整校验命令；项目没有的那几行直接删掉。
2. 工程标准——共享指南，以及项目自身的例外。
3. 代码地图——每个顶层目录一行，点名关键模块。
4. 边界——必须做 / 绝不做 / 先问。
5. 已确认的语言政策——参见[语言政策](language-policy.md)。
6. 项目约定——Agent 无法从代码猜出的决策。
7. 指向 `DEVELOPMENT.md`、`CONTRIBUTING.md`、`ARCHITECTURE.md` 的深入链接。

命令排在最前，因为那是 Agent 头一分钟就要用的东西。同时给出小范围形式与完整门禁——改一行时用聚焦的测试命令，提交前跑 `mise run check`——这样 Agent 不会默认去跑最昂贵的那条。

## 写可验证的规则

每条规则都必须说明一个 Agent 能执行、评审者能核对的行为。点名命令、路径或条件。

可验证：

```markdown
- 改动 `src/auth/` 下的文件时，运行 `mise run test -- src/auth/token.test.ts`。
- 绝不手改 `src/generated/` 下的文件；用 `mise run codegen` 重新生成。
- 新增依赖或改动 `ARCHITECTURE.md` 中的不变量前先问。
```

不可验证，因此没有用：

```markdown
- 处理认证代码时要小心。
- 确保一切正常。
- 遵循最佳实践。
```

## 嵌套文件

从一份根文件开始。只有当某个子目录树确实不同时，才在其中增加嵌套的 `AGENTS.md`：

- 它使用不同的包管理器、测试运行器或运行时。
- 它包含只能重新生成、不能手改的生成代码。
- 它带有额外的审批要求，例如数据库迁移或部署。
- 它有不适用于别处的 UI 或设计系统规则。

嵌套文件只记录自己的差异，其余一切沿用根文件。绝不在嵌套文件里重述根文件的规则。

## 保持精简

整份文件在每个任务开始时都会加载，因此体积是要反复支付的成本。

- 把信噪比最高的规则放在最前面。
- 链接到详细文档，而不是复制它们。
- 优先用机器化检查而非一段文字：Lint 工具、prek 或 CI 已经强制的规则不必再写一遍。
- 把子系统专属的指引放进嵌套文件，而不是让根文件不断膨胀。

让根文件能一遍扫读完。做不到时，该做的是分流与删除，而不是压缩字号。

## 绝不写入的内容

- 敏感凭据、令牌或内部主机名。
- 仓库里已有文档的副本。
- 面面俱到的目录清单——下一次重构就会过期。
- 应该留在 issue 或 pull request 里的临时任务笔记。
- 一概跳过校验的指令。

## 保持更新

命令、代码地图、边界或约定发生变化时，在同一个变更里更新 `AGENTS.md`。

过期的指令比缺失的指令更糟：Agent 会信心十足地照做，并交出没人要求过的改动。
