# 架构治理

## 架构不变量

项目应显式记录 AI Agent 不得在无意中破坏的架构约束。

用 `ARCHITECTURE.md` 记录当前的架构边界与不变量。

示例包括：

- 领域逻辑属于哪一层
- 哪些模块可以调用外部 API
- 认证边界
- 状态管理边界
- Databricks 访问边界
- 前后端职责划分
- 依赖方向
- 集成边界

保持这份文档精简。

它应当回答：

> **关于当前架构，哪些事实必须始终成立?**

何时需要这份文档，见[必备项目文档](project-documentation.md)。

## 架构决策记录

重大架构决策使用 ADR。

每项重要架构决策应单独存放，并遵循统一的 ADR 结构。

ADR 应说明：

- 背景
- 决策
- 考虑过的替代方案
- 理由
- 后果

该结构采用共享的 [ADR 模板](../../../templates/adr.template.md)。

ADR 不是不可更改的法律。

它们是防止意外改动的架构护栏，尤其在 AI Agent 修改代码库时。

当用户请求与某项 ADR 冲突时：

1. 理解用户的真实意图。
2. 弄清该 ADR 存在的原因。
3. 评估更改该决策的影响。
4. 在合理的情况下，优先选择与既有架构兼容的方案。
5. 如果架构确实需要变更，说明其影响。
6. 明确更新或废止该 ADR。

禁止悄悄违反 ADR。

当用户不确定架构是否应当改动时，先帮助分析后果，再实施变更。
