# 架构治理

## 架构不变量

项目应明确记录 AI Agent 不得无意中违反的架构约束。

使用 `ARCHITECTURE.md` 记录当前架构边界和不变量。

示例包括：

- 领域逻辑属于哪一层
- 哪些模块可以调用外部 API
- 认证边界
- 状态管理边界
- Databricks 访问边界
- 前后端职责划分
- 依赖方向
- 集成边界

保持本文档简洁。

本文档应回答：

> **关于当前架构，哪些事实必须始终成立？**

本文档的适用条件见[必备项目文档](project-documentation.md)。

## 架构决策记录

对重大架构决策使用 ADR。

每项重要的架构决策都应单独记录，并采用统一的 ADR 结构。

ADR 应说明：

- 背景
- 决策
- 考虑过的替代方案
- 理由
- 后果

上述结构应使用共享的 [ADR 模板](../../../templates/adr.template.md)。

ADR 不是不可更改的铁律。

它们充当架构护栏，帮助防止意外改动，尤其是在 AI Agent 修改代码库时。

当用户请求与某项 ADR 冲突时：

1. 理解用户的真实意图。
2. 弄清该 ADR 存在的原因。
3. 评估修改该决策的影响。
4. 在合理的情况下，优先选择与既有架构兼容的方案。
5. 如果架构确实需要变更，说明其影响。
6. 明确更新或废止该 ADR。

禁止悄悄违反 ADR。

当用户不确定架构是否应当改动时，先帮助用户分析后果，再实施变更。
