# フロントエンドフレームワーク：Vite vs Next.js

## 判定

推奨 — フロントエンドフレームワークは Vite をデフォルトとし、Next.js はフルスタックの React 機能が本当に必要な場合に限り選択する。

判断基準：

- デフォルトでは Vite を使う。
- フルスタックの React アプリケーションが必要な場合に限り Next.js を使う。
- Vite より多機能だからという理由だけで Next.js を選んではならない。
- Next.js の複雑さに見合う利点がない場合は Vite を選ぶ。

## 使用する場面

### Vite

- フルスタックフレームワークを必要としない、シンプルで高速なフロントエンドアプリケーション。
- サーバーサイドレンダリング（SSR）やフレームワーク管理のサーバールートが不要な場合。

### Next.js

- サーバーサイドレンダリング、サーバールート、統合されたデータ取得を備えたフルスタックの React アプリケーションが必要な場合。

## 避けるべき場面

### Vite

- サーバーサイドレンダリングや統合されたフルスタックの React 機能が必要な場合。

### Next.js

- Vite より多機能であること以外に選ぶ理由がない場合。
- Next.js の複雑さに見合う価値がない場合 — この場合は Vite を使う。

## 長所

### Vite

- 設定が最小限で、開発サーバーが高速である。
- 扱う概念が少なく、フレームワークによる制約も少ない。

### Next.js

- サーバーサイドレンダリング、ルーティング、データフェッチを統合したフルスタック React 機能を備える。
- これらの機能が本当に必要な場合に、単一のフレームワークで対応できる。

## トレードオフ

### Vite

- フルスタックフレームワークではないため、サーバーサイド機能は別途追加する必要がある。
- Vite をアップグレードする際は、プラグインの互換性を確認しなければならない。

### Next.js

- アーキテクチャ、規約、運用面のいずれも、Vite より複雑である。
- メジャーバージョンのアップグレードでは、関連プラグインと連携機能の互換性をレビューする必要がある。

## バージョン方針

### Vite

- 新規プロジェクトでは最新の安定版 Vite を優先する。
- Vite プラグインは、最新の互換バージョンを優先する。
- Vite のアップグレード時には、プラグインの互換性を確認する。
- 具体的な互換性上の理由がない限り、プロジェクトを旧バージョンに留めてはならない。

### Next.js

- 新規プロジェクトでは最新の安定版 Next.js を優先する。
- 関連プラグインと連携機能は、最新の互換バージョンを優先する。
- メジャーバージョンのアップグレード時には、互換性をレビューする。

## 利用ルール

- フロントエンドアプリケーションにはデフォルトで Vite を使う。
- フルスタックの React 機能が実際に必要な場合に限って Next.js を使い、規模や機能数の多さだけで選んではならない。
