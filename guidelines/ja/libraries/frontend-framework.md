# フロントエンドフレームワーク：Vite vs Next.js

## 判定

推奨 — フロントエンドフレームワークは Vite をデフォルトとし、Next.js はフルスタック機能が本当に必要な場合に限り選択する。

判定基準：

- デフォルトでは Vite を使う。
- プロジェクトがフルスタックの React アプリケーション、または Next.js を選ぶ十分な理由となる機能を必要とする場合に限り、Next.js を使う。
- Vite より高機能であるという理由だけで Next.js を選んではならない。
- Next.js の追加の複雑さが価値を生まない場合は、Vite を選ぶ。

## 使用する場面

### Vite

- シンプルで高速なフロントエンドであり、フルスタックフレームワークが不要なアプリケーション。
- サーバーサイドレンダリングやフルスタック機能が不要な場合。

### Next.js

- プロジェクトがフルスタックの React アプリケーションを必要とする場合。
- プロジェクトが Next.js を選ぶ十分な理由となる機能を必要とする場合。

## 避けるべき場面

### Vite

- プロジェクトが Next.js を選ぶ十分な理由となるフルスタック機能を必要とする場合。

### Next.js

- Next.js のほうが Vite より高機能であることしか根拠がない場合。
- Next.js の追加の複雑さが価値を生まない場合 — その場合は Vite を使う。

## 長所

### Vite

- 設定が最小限で、開発サーバーが高速である。
- 扱う概念が少なく、フレームワークによる制約も少ない。

### Next.js

- サーバーサイドレンダリング、ルーティング、データフェッチを統合したフルスタック React 機能を備える。
- これらの機能が本当に必要な場合に、単一のフレームワークで対応できる。

## トレードオフ

### Vite

- フルスタックフレームワークではないため、サーバーサイド機能は別途追加する必要がある。
- Vite をアップグレードする際は、プラグインの互換性を確認しなければならない。

### Next.js

- アーキテクチャ、規約、運用面のいずれも、Vite より複雑である。
- メジャーバージョンのアップグレードでは、関連プラグインと連携機能の互換性をレビューする必要がある。

## バージョン方針

### Vite

- 新規プロジェクトでは最新の安定版 Vite を優先する。
- Vite プラグインは、最新の互換バージョンを優先する。
- Vite のアップグレード時には、プラグインの互換性を確認する。
- 具体的な互換性上の理由がない限り、プロジェクトを旧バージョンに留めてはならない。

### Next.js

- 新規プロジェクトでは最新の安定版 Next.js を優先する。
- 関連プラグインと連携機能は、最新の互換バージョンを優先する。
- メジャーバージョンのアップグレード時には、互換性をレビューする。

## 利用ルール

- フルスタックフレームワークが不要な、シンプルで高速なフロントエンドアプリケーションには Vite を使う。
- プロジェクトがフルスタックの React アプリケーション、または Next.js を選ぶ十分な理由となる機能を必要とする場合は、Next.js を使う。
- Next.js のほうが Vite より高機能であるという理由だけで、Next.js を使ってはならない。
- Next.js の追加の複雑さが価値を生まない場合は、Vite を選ぶ。
