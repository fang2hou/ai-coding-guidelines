# フロントエンドフレームワーク: Vite vs Next.js

## 判定

推奨 — Vite をデフォルトのフロントエンドフレームワークとし、Next.js はフルスタック機能が本当に必要な場合に限って選択する。

判定基準:

- デフォルトでは Vite を使う。
- プロジェクトがフルスタックの React アプリケーション、または Next.js を選ぶ正当な理由となる機能を必要とする場合に限り、Next.js を使う。
- 「Next.js のほうが Vite より高機能」という理由だけで Next.js を選んではならない。
- Next.js の追加の複雑性が価値をもたらさない場合は、常に Vite を選ぶ。

## 使用する場面

### Vite

- アプリケーションがシンプルで高速なフロントエンドであり、フルスタックフレームワークが不要である。
- サーバーサイドレンダリングやフルスタック機能を必要としない。

### Next.js

- プロジェクトがフルスタックの React アプリケーションを必要とする。
- プロジェクトが、Next.js を選ぶ正当な理由となる機能を必要とする。

## 避けるべき場面

### Vite

- プロジェクトが、Next.js を選ぶ正当な理由となるフルスタック機能を必要とする。

### Next.js

- 「Next.js のほうが Vite より高機能である」以外に根拠がない。
- Next.js の追加の複雑性が価値をもたらさない — この場合は Vite を使う。

## 長所

### Vite

- 設定が最小限で、開発サーバーが高速である。
- 覚える概念が少なく、フレームワーク由来の制約も少ない。

### Next.js

- サーバーサイドレンダリング、ルーティング、データフェッチを備えた、一体型のフルスタック React 機能。
- それらの機能が本当に必要な場合、単一のフレームワークでまかなえる。

## トレードオフ

### Vite

- フルスタックフレームワークではないため、サーバーサイドの機能は別途追加する必要がある。
- Vite をアップグレードする際は、プラグインの互換性を確認しなければならない。

### Next.js

- アーキテクチャ、規約、運用面のすべてにおいて、Vite より複雑性が増す。
- メジャーバージョンのアップグレードでは、関連プラグインと統合部分の互換性をレビューする必要がある。

## バージョン方針

### Vite

- 新規プロジェクトでは最新の安定版 Vite を使う。
- Vite プラグインは最新の互換バージョンを使う。
- Vite のアップグレード時にはプラグインの互換性を確認する。
- 具体的な互換性の理由がない限り、プロジェクトを古いバージョンに留めてはならない。

### Next.js

- 新規プロジェクトでは最新の安定版 Next.js を使う。
- 関連プラグインと統合部分は最新の互換バージョンを使う。
- メジャーバージョンのアップグレード時には互換性をレビューする。

## 利用ルール

- フルスタックフレームワークが不要な、シンプルで高速なフロントエンドアプリケーションには Vite を使う。
- プロジェクトがフルスタックの React アプリケーション、または Next.js を選ぶ正当な理由となる機能を必要とする場合は Next.js を使う。
- 「Next.js のほうが Vite より高機能」という理由だけで Next.js を使ってはならない。
- Next.js の追加の複雑性が価値をもたらさない場合は Vite を選ぶ。
