# mise

## 必須化

`mise` をすべてのプロジェクトで必須とする。

mise は、次の項目について、プロジェクトレベルで信頼できる唯一の情報源である。

- ランタイムのバージョン
- CLI ツールのバージョン
- 開発ツール
- 環境構成
- プロジェクト共通のタスク
- CI が使用するツールチェーンのセットアップ

mise で管理するツールの例は、次のとおりである。

- Node.js
- pnpm
- Python
- uv
- Databricks CLI
- Cocogitto
- prek
- その他のプロジェクト CLI ツール

mise で要件を満たせる場合は、別の汎用ツールマネージャーを導入しない。

これは、[中核となるエンジニアリング原則](../principles/core-principles.md)に示された中心原則を、ツールチェーンレベルで適用したものである。

## 役割分担

mise が管理するのは、Node.js、pnpm、uv、リンターなどのランタイムとツールのバイナリだけである。

各言語のパッケージと環境は、各言語専用のパッケージマネージャーでのみ管理する。Node では pnpm、Python では uv を使う。

言語のパッケージを mise 経由でインストールしない。

この役割分担は意図的なものである。1 回の `mise install` でツールチェーン全体をセットアップでき、追加のグローバルインストールも不要になる。一方、各エコシステムでは、それぞれのベストプラクティスに沿った固有のパッケージマネージャーを使い続けられる。

## バージョン方針

mise は可能な限り最新版を使う。

プロジェクトの保守では、理由なく古いバージョンに固定せず、mise 自体を最新に保つ。

## ツールのライフサイクル

プロジェクトで使われなくなったツールは、mise の設定から削除する。

不要になったツールをプロジェクト環境に残さない。

## タスク

`mise tasks` をプロジェクト共通のタスクインターフェースとして使う。

プロジェクトの代表的な処理は、次のようなコマンドで実行できるようにする。

```bash
mise run dev
mise run lint
mise run format
mise run typecheck
mise run test
mise run e2e
mise run check
mise run build
mise run deploy
```

言語固有のタスク定義は、適切であれば各エコシステムに残してよい。

たとえば、フロントエンドのスクリプトは `package.json` に記述し、pnpm 経由で実行してよい。

その場合、プロジェクト専用の別タスクシステムを作るのではなく、該当するワークフローを mise タスクとして公開する。

たとえば：

```text
mise task
    -> pnpm script
        -> underlying frontend tool
```

## ローカルと CI の一致

CI/CD でも、可能な限り mise を使う。

ローカル開発用と CI 用に、まったく別のツールチェーン定義を維持してはならない。

どちらの環境でも、プロジェクトが管理する同じツール群を使う。

## mise MCP

AI 環境が MCP をサポートし、プロジェクトのワークフローで mise MCP との連携が役立つ場合は、mise MCP の設定を優先する。

ユーザーが MCP 対応環境を使っているにもかかわらず mise MCP が設定されていない場合、エージェントは独自のプロジェクト管理の仕組みを作るのではなく、mise MCP の追加設定を支援してよい。
