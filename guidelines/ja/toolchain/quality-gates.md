# 品質ゲート

## prek

標準のプリコミットフレームワークとして `prek` を使う。

ユーザーが明示的に例外を承認しない限り、別のプリコミットフレームワークを導入しない。

### 採用しない代替案

* pre-commit
* Lefthook

## デフォルトのチェックセット

リポジトリの prek 設定には、プロジェクトに関係する高速なチェックを含める。

デフォルトでは次を含める。

* リント
* フォーマットのチェック
* 言語固有の静的チェック
* セキュリティ関連のチェック
* 適切な場合の依存関係チェック
* シークレットスキャニング

## チェックを高速に保つ

プリコミットのチェックは、意味のあるものにとどめる。

フック設定を網羅的に見せかけるためだけに、高コストなチェックを追加しない。

毎コミットで実行するチェックは、人間にも AI エージェントにも頻繁に使える速度を維持する。

## ローカルと CI の一致

GitHub でホストするリポジトリでは、GitHub Actions が同じプロジェクト設定で等価なチェックを実行し、ローカルと CI の検証が乖離しないようにする。

CI の階層モデルについては [GitHub Actions](../toolchain/github-actions.md) を、同じツール群へのタスクベースのアクセスについては [mise](../toolchain/mise.md) を参照。

## 検証のエントリーポイント

実用可能な限り、関係する品質ワークフローを mise タスクとして公開する。

たとえば、次のコマンドを:

```bash
mise run check
```

プロジェクトの主要な検証ワークフローへの、予測可能なエントリーポイントとする。
