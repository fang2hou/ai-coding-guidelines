# 言語ポリシー

言語の切り分けはプロジェクトの制約であり、明示的に扱わなければならない。

次の 3 つの概念は互いに独立である。

1. 会話言語
2. ソースコードの言語
3. プロダクト/UI 言語

一つの言語から別の言語を推測してはならない。

プロジェクトとして有効な構成には、次のようなものもある。

```text
Conversation: Chinese
UI: Japanese
Code: English
```

これらの言語は互いに分離し、それぞれが自然なものでなければならない。

## コードの言語

ソースコードはすべて標準的な英語で書く。ただし、意図的に他言語を含むリテラル値は例外とする。

次の要素は英語で書かなければならない。

- 変数名
- 関数名
- メソッド名
- クラス名
- 型名
- インターフェース名
- 列挙型名
- モジュール名
- ファイル名
- ディレクトリ名
- コードコメント
- ドキュメント文字列
- 設定の識別子
- 内部のシンボル識別子

コードの識別子やコメントに英語以外の言語を使用しないこと。

特に、次のものを使用してはならない。

- 日本語のかな文字
- 日本語ベースの識別子
- 中国語ベースの識別子
- ピンイン(pinyin)による識別子
- ローマ字(romaji)による識別子

禁止される識別子と、置き換える標準的な英語の例を示す。

```text
kokyakuName   -> customerName
shinseiStatus -> applicationStatus
kehuName      -> customerName
yonghuId      -> userId
```

ASCII の要件を満たすという理由だけで、英語以外の単語をラテン文字に音訳しないこと。

求められているのは**標準的な英語**であり、単なる ASCII ではない。

### リテラル値

リテラル値として他言語のテキストを意図的に含めることは認められる。該当するのは次のとおりである。

- UI の表示文言
- ローカライズリソース
- ユーザー向けのエラーメッセージ
- ローカライズされた内容を含むテストフィクスチャ
- ユーザーコンテンツの例
- 元の形式を保持しなければならないドメインデータ

リテラル値が存在するからといって、英語以外の変数名やコメントが許されるわけではない。

## 会話言語

ユーザーが使用する言語で、自然にコミュニケーションをとること。

会話には次の性質が求められる。

- 自然であること
- 友好的であること
- 明瞭であること
- その言語として慣用的であること
- ユーザーのコミュニケーションスタイルに合っていること

不必要な言語の混用を避ける。

中国語でやり取りしているとき、実装の内部で英語を使っているという理由だけで、英語のフレーズを差し込まないこと。

次のものを指す場合は英語が適切である。

- コードの識別子
- API 名
- ライブラリ名
- コマンド
- プロダクト名
- 確立された技術用語のうち、翻訳するとかえって分かりにくくなるもの

それ以外では、中国語で自然にコミュニケーションすること。

この原則はほかの言語でも同じである。

## プロダクトと UI の言語

プロダクトの言語を、会話言語だけから推測してはならない。

本格的なユーザー向けコンテンツを実装する前に、プロジェクトの言語方針がまだ文書化されていなければ、ユーザーに次の点を確認すること。

- UI の主要言語
- 追加でサポートする言語
- 該当する敬語レベルやトーンの要件

確認できた言語ポリシーは、プロジェクトドキュメントに記録すること([必須プロジェクトドキュメント](project-documentation.md)を参照)。

一度記録したら、同じ質問を繰り返さずに従うこと。

再確認が必要なのは、次の場合だけである。

- ユーザーが要件を明示的に変更した場合
- 新しい要件が、文書化されたポリシーと競合する場合
- 求められる対象言語が本当に曖昧な場合

ユーザーが会話言語を変えたからといって、黙って UI の言語を変更しないこと。

## 言語横断の品質

会話・コード・プロダクトで言語が異なるときは、より一層の注意が必要である。

言語間で文言を機械的に翻訳しないこと。

特に次の点を守ること。

- 中国語の影響を受けた日本語を作らない。
- 中国語の文構造を、不自然な形で日本語へ持ち込まない。
- 理由なく、実装で使っている英語を、自然な中国語の会話の中にそのまま差し込まない。
- 同じドメイン概念の訳語を、UI 全体でばらばらにしない。
- 中国語の開発者会話から、日本語の UI 用語を推測しない。
- 英語のソースコード識別子から、中国語の UI 用語を推測しない。

ユーザー向け UI 文言は、次の優先順位で評価すること。

1. 対象言語における標準的な用法
2. 正しい文法
3. 明確な意味
4. 適切な敬語レベル
5. 理解しやすさ
6. 使いやすさ
7. プロダクト全体との一貫性

UI のテキストは、直訳調や機械翻訳調ではなく、専門的で自然なものでなければならない。

重要な用語やトーンの選択に確信が持てないときは、勝手に慣例をでっち上げず、ユーザーに尋ねること。
