# 依存関係の管理方針

## 5 つの問い

依存関係を追加する前に、次の 5 つの問いに順番に答えること。

1. プロジェクトに適切な機能がすでに存在するか。
2. フレームワーク、プラットフォーム、標準ツールチェーンのいずれかが、すでに解決策を提供しているか。
3. その依存関係は実際の要件を満たすか。
4. 保守コストは許容範囲か。
5. 標準化されたツールチェーンと互換性があるか。

適用例：TypeScript プロジェクトで、実行時検証のために `zod` を追加する場合。

1. プロジェクト：実行時検証の仕組みは存在しない。
2. プラットフォーム：TypeScript の型はコンパイル時にしか存在せず、リクエストボディや環境変数は実行時には型付けされていない。
3. 要件：外部入力は実行時の境界を越えるため、使用前に検証が必要である。
4. 保守：単一用途のライブラリで API の規模が小さく、追跡すべき依存関係は 1 つである。
5. ツールチェーン：ランタイム専用のライブラリであり、pnpm でインストールし、oxlint や oxfmt と競合しない。

判断：`zod` を追加する。

同じ問いを適用すると、より弱い候補は却下される。`truncate` のような文字列ヘルパーライブラリは問い 3 で失敗する。3 行の明確なコードで実装できるため、依存関係は不要である。プラットフォームの `fetch` で要件をすでに満たせる場合、`axios` は問い 2 で失敗する。

ライブラリなしで明確に実装できる些細な機能のために、ライブラリを追加してはならない。

ユーザーの明示的な承認なしに、標準化されたツールを別の依存関係に置き換えてはならない。

## 互換性の参照先

互換性は、必須ツールチェーンを基準に評価すること。

- [TypeScript ツールチェーン](../toolchain/typescript.md) — pnpm、oxlint、oxfmt
- [Python ツールチェーン](../toolchain/python.md) — uv、ruff
- [品質ゲート](../toolchain/quality-gates.md) — prek
- [Git ワークフロー](../toolchain/git.md) — Conventional Commits のための Cocogitto

推奨ライブラリの選定については、[フロントエンドフレームワーク](../libraries/frontend-framework.md)と[Python API スタック](../libraries/python-api-stack.md)を参照すること。

これらの規則を支える標準化の原則は、[エンジニアリング基本原則](../principles/core-principles.md)で定められている。
